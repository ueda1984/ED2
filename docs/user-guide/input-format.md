# Input format

QS³-ED2 reads a **Fortran NAMELIST from standard input**. The paths in that
input are resolved from the directory in which the executable runs.
Record the source commit, the complete input, and every referenced list file.

## Start from a generated example

After building, run the chain generator from the repository root to create
a persistent example directory:

```bash
(cd script_chain && ./run.sh)
cd examples/chain
../../source/QS3ED2 < input.dat > output-second-run.dat
```

The final command runs the same calculation again. Observable files are
**appended to**, so use a separate working/output directory for an independent
result. See [Outputs](outputs.md). Other example directories are generated by
their corresponding `script_*/run.sh` scripts; they are not precomputed results
shipped in a fresh checkout. `make check` uses an isolated temporary test
directory and does not leave `examples/chain` in the checkout. See [Quickstart](../getting-started/quickstart.md).

Do not run the complete `make check-long` merely to create an input directory:
it includes the large cubic three-magnon example ex9. The individual examples
and their resource requirements are described in the [example pages](../examples/chain.md).

## NAMELIST syntax and required values

The first block is `&input_parameters`. It is followed by `&input_lancz` for
`ALG=1`, or `&input_TRLan` for `ALG=2`. `ALG=3` does not read a solver block.
The generated input files may include both solver blocks.

Use `/` or `&end` to terminate a block, quote strings, and use ordinary Fortran
numbers such as `1.0d-12`. Names are case-insensitive. **Unknown keys are input
errors**, not supported extension points. In particular, `eigvec` is not an
ED2 NAMELIST key; use `wr_wf`.

Except for `L1..L6=1`, `M1..M6=0`, and empty `FILE_S1..FILE_S6`, the
NAMELIST variables have **no explicitly initialized application defaults**.
Set every value used by your chosen calculation. A value observed after
omitting a key is not a documented default. Input validation is incomplete:
valid Fortran syntax does not prove that the model or symmetries are
physically consistent. Basic solver/count/site/spin/cap ranges are checked,
and NaN/Inf values in couplings, fields, spins, solver tolerances and saved
eigenpairs are rejected. These guards do not establish symmetry validity,
checkpoint compatibility/normalization, or numerical convergence.

All `FILE_*` and `OUTDIR` input strings are limited to 100 characters in the
current implementation. Output directories must already exist. Include a
trailing `/` in `OUTDIR` and `FILE_wf`, because filenames are concatenated
directly to these strings.

## `&input_parameters`: complete key reference

### Sites and retained basis

| Key | Type | Required value or default | Meaning |
| --- | --- | --- | --- |
| `NOS` | INTEGER | Set explicitly; positive | Number of sites. Site indices in list files are 1-based. |
| `NODmin`, `NODmax` | INTEGER | Set explicitly; `0 <= NODmin <= NODmax` | Lower and upper total numbers of local spin-lowering operations. |
| `FILE_spin` | CHARACTER(100) | Required | `NOS` records, each containing the local spin `S_i`. |
| `FILE_NODmax` | CHARACTER(100) | Required | `NOS` records, each containing the local occupation cap. |

The occupation at site `i` is `n_i = S_i - m_i`, with integer
`0 <= n_i <= local_NODmax(i)` and the required input constraint
`0 <= local_NODmax(i) <= 2*S_i`. A cap above the physical spin range is
rejected rather than silently clamped. The retained product states obey

$$
\mathrm{NODmin} \le \sum_i n_i \le \mathrm{NODmax}.
$$

Use physical integer or half-integer spins and nonnegative integer local caps.
The supplied generators use `min(2*S_i, NODmax)` for each local cap. To retain
the full product space, set `NODmin=0`, `NODmax=sum_i 2*S_i`, and local caps
`2*S_i`; its dimension is `product_i (2*S_i+1)` before symmetry reduction.

A fixed occupation window is an **exact symmetry sector only when the
Hamiltonian conserves it**. For example, `NODmin=NODmax` selects a fixed total
`S^z` sector for a U(1)-conserving Hamiltonian. With transverse fields or other
terms that leave that sector, ED2 instead constructs the projected operator
`P H P`. It is then a truncation, not a calculation of the full Hamiltonian.

The basis counts and indices use default Fortran integers. Memory is not the
only size limit: combinatorial counts can overflow. Do not infer 64-bit basis
support from the wording of a runtime message.

### Spatial symmetries

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `L1..L6` | INTEGER | `1` | Orders of up to six site-permutation operations with compatible scalar characters; each order must be positive. |
| `M1..M6` | INTEGER | `0` | Sector labels, conventionally `0 <= M_m < L_m`. |
| `FILE_S1..FILE_S6` | CHARACTER(100) | Empty | `NOS` records giving each site's image under the corresponding permutation. Only read when `L_m != 1`. |

A translation by one site is the list `2,3,...,NOS,1`, written one integer
per record. Each nontrivial list must be a permutation of `1..NOS` with the
stated order. Its action must preserve the local spins, occupation caps, and
**the entire Hamiltonian**, including oriented DM interactions and fields.
ED2's ordered products must enumerate the generated finite group uniformly,
and the requested scalar phases must obey the group's relations. Commuting
operations with compatible labels are a sufficient case. Translation and
reflection can also be combined in compatible zero/pi momentum sectors,
including ex9; arbitrary noncommuting generators and multidimensional
representations are not supported. See [Theory and algorithms](../theory/algorithms.md#spatial-symmetry-projection).
Defining `T_m` as the **active** action that moves each site's spin occupation
to the site in its image list, the phase convention is

$$
T_m |\Psi\rangle = e^{+2\pi i M_m/L_m}|\Psi\rangle.
$$

ED2 does not automatically prove these conditions. A calculation can terminate
normally with an invalid symmetry input. An empty projected sector stops with
`THS = 0.`. The input interface implements site permutations; it does not
provide a separate spin-inversion-parity selector or arbitrary multidimensional
point-group representations.

### Hamiltonian lists and sign conventions

| Key | Type | Required value | Meaning |
| --- | --- | --- | --- |
| `NO_one` | INTEGER | Nonnegative | Number of field records read. |
| `NO_two` | INTEGER | Nonnegative | Number of two-site interaction records read. |
| `FILE_hvec` | CHARACTER(100) | Existing file | Field list: `i hx hy hz`. |
| `FILE_xyz_dm_gamma` | CHARACTER(100) | Existing file | Bond list: `i j Jx Jy Jz Dx Dy Dz Gx Gy Gz`. |

There is no header in either list. ED2 reads exactly the specified number of
records. Both files are opened even when their count is zero; use an existing
empty file in that case. Each bond must connect distinct, valid sites.

The field convention is **plus**:

$$
H_{\mathrm{field}} = \sum_a \mathbf h_a\cdot\mathbf S_{i_a}.
$$

For a physical Zeeman term `-B.S`, put `h=-B` in the input. The field values
on a record belong to that record's specified site.

A directed bond record `(i,j)` contributes

$$
H_{ij} = \sum_{\alpha=x,y,z} J^\alpha S_i^\alpha S_j^\alpha
+ \mathbf D\cdot(\mathbf S_i\times\mathbf S_j)
+ G^x(S_i^yS_j^z+S_i^zS_j^y)
+ G^y(S_i^zS_j^x+S_i^xS_j^z)
+ G^z(S_i^xS_j^y+S_i^yS_j^x).
$$

`Gx,Gy,Gz` are the symmetric off-diagonal exchange coefficients, also called
`Gamma`. ED2 sorts each bond's site indices internally and reverses all three
DM components when it reverses the pair. To describe the same oriented
interaction after swapping `i,j` in your file, negate `Dx,Dy,Dz`; leave the
exchange and Gamma components unchanged. Separate records add, so do not
accidentally list both orientations of the same physical bond twice.

The physical row generators retain off-diagonal operator channels only when
the magnitude of their combined coefficient exceeds `1.0d-15`. This is an
absolute, internal threshold, not a user-controlled solver tolerance. Scaling
very small model coefficients can therefore change which channels are retained.

### Hamiltonian cache

| Key | Type | Meaning |
| --- | --- | --- |
| `wk_dim` | INTEGER | Number of initial **matrix rows** cached for iterative solvers. Any negative value selects the full projected dimension; `0` caches no rows; a positive value is capped at the projected dimension. |
| `MNTE` | INTEGER | Explicit off-diagonal transition slots per cached row when nonnegative; one diagonal slot is added. A negative value selects an automatic conservative capacity. |

Set both explicitly. `wk_dim=-1, MNTE=-1` is a useful starting point for a
small model. A full cache can be too large for a big model; smaller `wk_dim`
trades storage for repeated row generation. An insufficient explicit `MNTE`
can stop with `MNTE is too small`. The printed `Optimal MNTE` is a conservative sizing hint for the
rows examined during cache construction; the current counter includes one
extra slot relative to the minimum off-diagonal capacity. It is not a proof
for all future inputs.

These controls and the optional CSR environment variables apply to `ALG=1`
and `ALG=2`. `ALG=3` builds a dense matrix and does not use this cache path.
See [Hamiltonian caching, performance, and memory](performance-and-memory.md)
for the exact flags, prerequisites, and allocation accounting.

### Solver selection and output

| Key | Type | Meaning |
| --- | --- | --- |
| `ALG` | INTEGER | `1`: conventional Lanczos ground state; `2`: thick-restart Lanczos; `3`: dense Hermitian diagonalization with LAPACK. |
| `wr_wf` | INTEGER | `1` writes binary eigenvectors and `energy.dat` under `FILE_wf`; `0` disables this. |
| `re_wf` | INTEGER | `1` loads saved vectors for the iterative-solver paths; `0` computes them. Dense `ALG=3` always diagonalizes. |
| `FILE_wf` | CHARACTER(100) | Existing directory/prefix for wavefunction I/O; include a trailing `/`. |
| `OUTDIR` | CHARACTER(100) | Existing directory/prefix for energy and observable files; include a trailing `/`. It does not redirect standard output. |
| `cal_lm` | INTEGER | `1` computes local magnetizations; `0` disables this. |
| `cal_cf` | INTEGER | `1` computes the requested two-site correlations; `0` disables this. |
| `NO_two_cf` | INTEGER | Nonnegative number of pair records read when `cal_cf=1`. |
| `FILE_two_cf` | CHARACTER(100) | With `cal_cf=1`, an existing file containing `NO_two_cf` records `i j` with distinct valid sites. |

The main program evaluates observables for **one vector**, normally the lowest
computed state. Requesting many eigenpairs does not produce observables for
all of them. Read the restart restrictions and exact column formats in
[Outputs](outputs.md). Select flag values `0` or `1` explicitly; malformed flag
values are not consistently rejected by this version.

## `&input_lancz` (`ALG=1`)

All four values must be specified.

| Key | Type | Meaning and usable range |
| --- | --- | --- |
| `lnc_ene_conv` | REAL(8) | Positive stopping tolerance on relative changes in the estimated lowest energy; **not** a residual-norm tolerance. |
| `minitr` | INTEGER | Positive minimum iteration number before periodic convergence checks. |
| `maxitr` | INTEGER | Positive maximum number of Lanczos steps; limited internally to the projected dimension. |
| `itrint` | INTEGER | Positive interval between convergence checks and log lines. Zero is invalid. |

Example:

```text
&input_lancz
  lnc_ene_conv=1.0d-12, minitr=5, maxitr=1000, itrint=5
/
```

The implementation reconstructs a single eigenvector from a second Lanczos
pass. A numerically closed Krylov subspace terminates without dividing by a
vanishing next-vector norm; a one-dimensional invariant subspace retains the
complete normalized starting vector. The relative energy change uses
`abs(E_old-E_new)/max(abs(E_old),abs(E_new),tiny(1d0))`, which avoids division
by zero but does not replace a residual test. The first Ritz estimate does not
count as convergence; at least two Ritz checks are required unless the Krylov
subspace closes or spans the available space. Check the printed
`Residual norm ||H psi - E psi||`, especially near zero energy, and compare
small systems with dense diagonalization. Energy stagnation and an ordinary
process exit are not sufficient convergence tests. See
[Theory and algorithms](../theory/algorithms.md).

## `&input_TRLan` (`ALG=2`)

All seven values must be specified.

| Key | Type | Meaning and usable range |
| --- | --- | --- |
| `NOE` | INTEGER | Positive number of lowest eigenpairs to report. |
| `NOK` | INTEGER | Number of Ritz vectors retained at restart; require `NOE <= NOK`. |
| `NOM` | INTEGER | Krylov-space size. Values below `2*NOK` are raised to `2*NOK`; the resulting value must not exceed the projected dimension. |
| `maxitr` | INTEGER | Positive maximum number of restart iterations, not simply the number of Hamiltonian applications. |
| `lnc_ene_conv` | REAL(8) | Positive relative energy-change stopping tolerance across the retained states; not a residual bound. |
| `i_vec_min`, `i_vec_max` | INTEGER | Saved/read vector range; use `1 <= i_vec_min <= i_vec_max <= NOE`. For ground-state observables after restart, require `i_vec_min=1`; an excited-state-only restart with `cal_lm=1` or `cal_cf=1` is rejected. |

The code checks positive counts and tolerance, `NOE <= NOK`, the vector
range, and the resulting workspace against the projected dimension. The
relative energy change uses a denominator bounded below by `tiny(1d0)`;
each reported state also has a printed residual norm. Reaching the restart
limit before the convergence test succeeds causes a nonzero error exit
(`TRLan restart limit reached before convergence`) without final result files.

This single-vector TRLan implementation cannot construct missing directions
when its Krylov subspace closes before the required workspace is filled. It
terminates with a nonzero error status and `TRLan Krylov breakdown`, instead
of producing invalid vectors. For small or highly degenerate spaces, use
`ALG=3`. Do not copy large TRLan workspace values from another example.

## Reproducibility and troubleshooting

Keep the source commit, compiler and flags, BLAS/LAPACK backend, OpenMP and
BLAS thread counts, complete input files, and complete output log. The public
input interface has no random-seed control; random starting vectors can differ
between runs and thread counts. A development-fork parameter is not necessarily
accepted by this source version.

If a file cannot be opened, check the runtime directory, exact filename, the
100-character path limit, and the trailing slash for output prefixes. If a
sector is empty or the results are unexpected, verify local spins, caps,
occupation conservation, and every imposed spatial symmetry before changing
solver parameters. Check the reported energies and observables, not only the
presence of output files.
