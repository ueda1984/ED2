# 1000-site-scale PRESTO benchmark: staged admission protocol (2026-11-18)

**Status:** source capacity improvement and independent symmetry preflight only. No 1024-site ED2 calculation, no exclusive-node allocation, and no PBS submission has yet been performed. Do **not** use the 12x12/16x16 benchmark script as an automatic 1024-site production launcher.

## Rationale

The earlier 12x12/16x16 runs are needed to validate equal-sector legacy/fast physics and characterize OpenMP overhead. A distinct 1024-site square-lattice calculation is needed to demonstrate a large-site three-magnon sector. These are *not* general Hilbert-space ED results: the full sector dimension is `comb(1024,3)=178433024`, and the reduced subspaces can be much smaller.

At 32x32, the space group has `1024*8=8192` elements. The previous 4-million-site-image guard rejected `8192*(1024+1)=8396800` permutation entries and forced the legacy basis builder. The experimental change raises this **one-time validation** cap to 12 million entries, about 48 MB of int32 permutation storage, while preserving the 8192-element group bound and all group-closure/character tests. Other arrays, basis construction and solver memory are additional. This is **not** evidence of successful large-site execution.

## Required stages before any large exclusive-node job

1. CI: existing point-group physical regressions, old-vs-fast agreement, invalid normal forms, OpenMP deterministic basis, and independent 26x26/32x32 Burnside dimensions. A capacity preflight does not replace an actual group-closure execution.
2. **One-time bounded 1024-site group validator**: instrument or test the real Fortran `validate_noncommuting_action` with 32x32 C4v generators and character phases, without enumerating the 178-million-state raw Hilbert sector. Record elapsed time, peak RSS, and accepted/fallback path. Compare with a separately implemented Python permutation/character oracle. This is still outstanding.
3. **Memory and representation audit**: examine `THS`, `NODmax`, orbit visited bitsets, rank/index storage, `ham2vec` and cache allocations. 178 million raw states can imply hundreds of MB to multiple GB even before Krylov vectors, depending on representation; 64 GB is **not** assumed sufficient without an actual allocation estimate.
4. **Small large-site smoke**: 26x26 and 32x32 with only one thread and a deliberately limited number of iterations, explicit timeout and peak RSS capture, with no performance claims.
5. **Independent PRESTO site-policy attestation**: `place=exclhost` request, actual `exec_vnode`, CPU affinity and other jobs checked by the operator. Only then stage a reviewed, pinned Git source archive and manually submit a new, separate PBS job.
6. **Full benchmark**: after a smoke and memory review, compare same-sector forced-legacy and validated-fast only where the legacy run is feasible; retain timed-out legacy results as censored data rather than invented speedups. Report translation-only and point-group results separately, with 2 warmups, 7 repeats only when feasible within the walltime budget.

The **1000-site ring** (translation plus inversion, dihedral group) is a separate geometry and is not generated by the current square-lattice benchmark driver. It requires its own invariant bond generator, character projector and sector verification before running. Do not label a 32x32 square lattice as a ring test.

## Non-executing admission commands

```sh
python3 tools/cpc_large_sector_preflight.py --sizes 12,16,20,26,32
python3 tools/cpc_large_sector_preflight.py --sizes 26,32 --independent-projector
```

The first prints exact combinatorial and validation-buffer estimates. The second also computes independent character-projected dimensions and is more expensive; it **does not run ED2**.

## Paper claim boundary

State separately (i) exact numerical equivalence on tractable small/medium sectors, (ii) group validator accepting a 1024-site C4v normal form, (iii) successful 1024-site eigensolver convergence and direct residual, and (iv) exclusive-node timing. Do not claim (ii)-(iv) merely because the guard now admits 8,396,800 site images.
