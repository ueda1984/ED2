# PRESTO cross-library benchmark with **latest** ED2 main

**Status (2026-11-19): staging/submission design only. No PRESTO job has
been submitted, no nodes have been allocated and NO cross-library
same-node timing ratios exist.** This is an independent Draft PR on
main; it never merges code from other PRs or modifies production Fortran.

## Critical release/main gate

1. **Source of truth for ED2:** `origin/main` at the exact instant the
   stage is created. Not the launch PR branch, not an old experimental
   PR #16 or #21 commit, and not the upstream QS-Cube/ED2 repository.
   Store the 40-digit SHA and an immutable `git archive`.
2. **Benchmark tools:** `codex/ed2-cross-library-benchmark-protocol-20261119`
   (PR #36), pinned independently by SHA. The tools do not imply that
   their source is the ED2 executable.
3. **PRESTO launch scripts:** this separate Draft PR, third pinned SHA.
   `stage_latest.sh` does not change the current checkout or main.
4. If other chat/agent merges new code into main after staging,
   **make a NEW stage**, not a silent update or overwrite. The
   `preflight.py --mode submit` command verifies the remote main SHA
   again and rejects a stale stage.

**As inspected at 2026-11-19, fork-main
`0313933964d2955365c312ce681b5828fe91f857` has generic complex CSR,
coefficient bounds and direct two-pass build, but does NOT contain the
independently certified cubic `O_h` optimization stack and
`ED2_LANCZOS_TWO_STAGE` / `ED2_DIAGNOSTICS` /
`ED2_PHASE_TIMING` instrumented native benchmark interface.
Draft PRs #13--#21 are not automatically in main. Therefore a real
N1000 / m3 Gamma/Oh A1g same-node benchmark is currently blocked,
until appropriate reviewed capabilities have landed on main.**
This constraint avoids relabeling experimental code as latest-main ED2.

The hard gate requires these source markers before **manual submission**:

- `ED2_CUBIC_FAST_GROUP_VALIDATION`
- `ED2_CUBIC_ANCHORED_REP`, `ED2_CUBIC_ANCHORED_BASIS`
- `ED2_CUBIC_LOCAL_BOND_CACHE`, `ED2_CUBIC_DIRECT_HOP_TABLE`
- `ED2_LANCZOS_TWO_STAGE`, `ED2_PHASE_TIMING`, `ED2_DIAGNOSTICS`

Source markers are necessary but not sufficient: the native runner additionally
checks exact fast-path stdout markers, the A1g dimension, eigenvalues,
the directly certified Ritz residual, and all phase records.
If a future reviewed main uses renamed options, **review and update
the gate before submitting**; do not disable it.

## Physical workload

Spin-1/2, periodic 10×10×10 simple cubic (N=1000), exactly three
conserved spin-down magnons, Gamma/Oh A1g dimension **4299**
(raw fixed-m sector `C(1000,3)=166167000`).

The *same* 9000-bond J1-J2 XXZ Hamiltonian as independently verified in
PR #36 and ED2 PR #16:

- 3000 axial bonds, (Jxy,Jzz)=(1.00,0.77)
- 6000 face-diagonal bonds, (Jxy,Jzz)=(0.31,0.19)
- no external field or DM coupling, `wk_dim=-1`, `MNTE=64` for native ED2
- all-up reference energy 862.5, independent A1g lowest energy
  **847.3078940655731** (require |Delta E| <= 1e-8)
- the PR36 physical-model SHA256 must equal
  `a774358f0c69f81982d3495707f45433acd223b3a40aacd109304fb371903fd7`.

ED2's native input is independently generated by `runner.py`, using
the proven three translation generators and the 4×4×3 = 48-element
cubic point-group normal form. The QuSpin side uses independently
validated 4×3×2×2 generators. Both character sets describe Gamma,
the trivial A1g irrep. Sector dimension, energy and residual must agree.
A U(1)-only XDiag probe is **not** compared to the A1g ED2/QuSpin
block; implementing a symmetry-matched XDiag adapter is separate work.

## PRESTO compute allocation

The reviewed request, based on prior ED2 PRESTO workloads:

```
#PBS -q standard
#PBS -l select=1:ncpus=96:mem=64gb
#PBS -l place=exclhost
#PBS -l walltime=06:00:00
```

These are **requests, not independent proof of exclusivity**. A PRESTO
administrator/operator must verify the queue's true placement semantics,
the CPU allocation, competing jobs and runtime policy before any
publication use. The launcher checks `PBS_JOBID`, `PBS_NODEFILE`,
actual `qstat -f` queue/select/place and `exec_vnode`; requires
`ED2_EXCLUSIVE_CONFIRMED=1` following a site/operator policy review.
It logs read-only `qstat/pbsnodes` and node topology. No automatic
`qsub` or job retries, and no scheduler/queue mutation.

## Preparation: immutable source staging (not a job)

Use an accessible local or PRESTO-login clone of **ueda1984/ED2**
with remote `origin` pointing to that fork. Staging needs GitHub
access, but the compute node does NOT.

Obtain the launch script without checking out or changing another
agent's worktree (example):

```bash
cd /path/to/ueda1984-ED2
git fetch origin refs/heads/codex/ed2-presto-cross-library-latest-main-20261119
git show FETCH_HEAD:tools/presto_cross_library/stage_latest.sh > ./stage-cross-latest.sh
# Use a NEW, not-yet-existing path:
bash ./stage-cross-latest.sh "$PWD" "$HOME/ed2-presto-stage-NEWID"
```

The script fetches **current** remote main, separately fetches PR36
benchmark ref and this launcher ref, archives all three at pinned SHAs
without modifying the worktree, and writes SHA256SUMS. It fails if
main moves *during* staging. Staged `launch.pbs` and `preflight.py`
are extracted for convenience.

Immediately before **manual** qsub, confirm main has not changed and
all native capabilities have been merged (it currently FAILS this gate):

```bash
STAGE="$HOME/ed2-presto-stage-NEWID"
python3 "$STAGE/preflight.py" --stage "$STAGE" --mode submit \
  --repo /path/to/ueda1984-ED2
```

Only status `READY` with exit code **0** allows advancing.
After any later main merge: run `stage_latest.sh` again with a new
path, repeat the check, then submit. Never re-label old data as new main.

## External runtime preparation (no automatic pip install on compute nodes)

PRESTO's login-node `python3` may be older than that required
by QuSpin 1.0.1. Install a separate approved, compute-node-accessible
Python >=3.10 environment with **QuSpin 1.0.1** and compatible NumPy/
SciPy before paired submission. Provide the absolute Python binary
path as `ED2_QUSPIN_PYTHON`. Avoid modifying site-global modules or
system Python. The native driver only needs Python >=3.6.

The PBS wrapper runs `autoreconf -vfi`, builds the **pinned staged
main source** with `-O2 -fopenmp`, runs `make check`, and uses the
old PRESTO private OpenBLAS .so.0 link fallback if development
linker names are missing. Build/binary hashes and logs are retained.
The QuSpin environment's version is checked *before* its trials.

## Manual first trial (after operator and main readiness checks)

Because `qsub -v` separates environment variables by commas, use
a **plus** between program names, not a comma.

First, the main-only native scientific pilot, 1 thread, one repetition:

```bash
mkdir -p "$HOME/ED2_CROSS_RESULTS"
qsub -v "ED2_STAGE=$STAGE,ED2_RESULTS_ROOT=$HOME/ED2_CROSS_RESULTS,ED2_EXCLUSIVE_CONFIRMED=1,ED2_PROGRAMS=ed2-cubic,ED2_THREADS=1,ED2_REPEATS=1,ED2_WARMUPS=0" \
  "$STAGE/launch.pbs"
```

Only after the native pilot succeeds and is independently audited,
the QuSpin paired feasibility run (same allocated node and model):

```bash
qsub -v "ED2_STAGE=$STAGE,ED2_RESULTS_ROOT=$HOME/ED2_CROSS_RESULTS,ED2_EXCLUSIVE_CONFIRMED=1,ED2_PROGRAMS=ed2-cubic+quspin,ED2_QUSPIN_PYTHON=/approved/quspin-venv/bin/python,ED2_THREADS=1,ED2_REPEATS=1,ED2_WARMUPS=0,ED2_TIMEOUT_SECONDS=1800" \
  "$STAGE/launch.pbs"
```

These commands are templates: **not executed by ChatGPT**. Verify
actual site privileges, queue and QuSpin installation first. For
final timing, use warmups >=1 and repetitions >=5 only after the pilot
establishes feasibility and resource budget. The runner alternates
case order across rounds, selects physical CPUs in the allocation,
pins processes, fixes one BLAS thread, hard-limits child virtual
memory (default 48 GiB) and wall time per trial (default 1800 s).

`ED2_PROGRAMS=ed2-legacy` and `ED2_PROGRAMS=ed2-legacy+ed2-cubic`
are reserved for the same main source's legacy-vs-specialized
**native** comparison; these can be very slow and should be attempted
only after operator-reviewed budget estimates. The specialized mode
requires actual native stdout proof markers; an option silently
ignored by an older executable is a **failure**, not a speed result.

## Data products / publication gate

Every PRESTO job creates a new, never-overwritten
`$ED2_RESULTS_ROOT/$PBS_JOBID` with:

- 3 immutable archive SHAs and executable SHA; build / regression logs
- exact physical input files and SHA256 per native trial
- all attempts, stdout, process wall/CPU/RSS and memory/time failures
- native physics: projected dimension, two-stage Lanczos certified
  eigenvalue, direct residual, number of H actions and stage timing
- QuSpin physics: actual 4299 dimension, eigenvalue, direct residual,
  basis/CSR/eigenpair timing; library versions in raw JSON
- `trials/plan.json`, `trials/trials.jsonl`, `trials/summary.json`
  with median and median absolute deviation (MAD)
- `qstat/pbsnodes` preflight/postflight and node hardware information.

This runner is experimental. **No data are publication-eligible
automatically**, even if all numerical checks pass. A separate named
operator must attest node exclusivity, process affinity, original
input hashes and actual overlapping jobs. Failed, timed out and
non-equivalent sectors cannot be discarded or counted as valid
completed measurements.
